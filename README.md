# 架子鼓

在浏览器里用电脑键盘，或者用手指敲屏幕，演奏一套原声架子鼓。页面是静态的，可以放到 GitHub Pages 上免费访问。

## 怎么演奏

打开页面，等「正在加载鼓的音色…」消失就可以敲。

- **电脑**：按鼓面上标出的键。可以同时按住几个键，声音会叠在一起，前一下不会被切断。按住不放时，会按系统的连发速度连击。
- **手机和平板**：请横过来握。手指点在鼓上就会响，多根手指可以同时敲不同的鼓。按下的瞬间出声，没有点击延迟。

键位按鼓在你面前的位置来排，从左到右。需要双手交替的鼓（吊镲、闭镲、三只嗵鼓、叮叮镲、军鼓）各有两个紧挨着的键，用两根手指轮流按，就像左右手轮流落槌。两次声音叠在一起，这一面鼓的两条采样也会轮换，滚奏不会那么死板。录音会把两个键都按时间记下来。

左手放在 `A` `S` `D` `F` `G`：`A` `S` 滚闭镲，`D` 点开镲，`F` `G` 和右手一起滚军鼓，向上 `Q` `W` 打吊镲，`E` `R` 打高音嗵鼓。右手放在 `J` `K` 滚落地嗵鼓，向上 `U` `I` 打叮叮镲、`T` `Y` 打中音嗵鼓，食指回到 `G` 和左手交替打军鼓。空格用拇指打底鼓。底鼓只留一个键，拇指好按；开镲多半是单手点一下，所以也是一个键。

## 录音、播放、节拍器和音量

- **录音**：点一下开始，再点一下结束。按钮上会显示已经录了多久。再录一次会换掉上一段。
- **播放**：按你敲的时间和顺序把刚才那段放出来，鼓面也会跟着亮。播放时你还可以接着敲，这些新敲的不会写进正在播放的那段。
- **清空**：删掉当前录音。
- **节拍**：打开节拍器。第一拍稍重一点，旁边有四拍的指示。拖动 **BPM** 改速度，范围是 40 到 220。节拍器的嘀声不会被录进去。
- **音量**：同时调节鼓和节拍器。音量和 BPM 会记在这台浏览器里。

## 伴奏

可以放一首没有鼓的音乐，自己跟着敲。

- **自己的文件**：点 **打开伴奏**，或把文件拖进页面。支持浏览器能播的格式，比如 mp3、wav、ogg、m4a、flac。文件只留在这台浏览器里，不会上传到任何服务器。上次选的曲会记在 IndexedDB 里，刷新页面还在，也不会自动播放。
- **内置曲目**：下拉菜单里有两段 CC0 无鼓伴奏，见下面的许可说明。
- **播放 / 暂停 / 停止**：停止会回到开头。进度条可以拖，旁边是当前时间和总时长。
- **循环**：放到结尾后再从头。
- **伴奏音量**：只调伴奏，不改变鼓和节拍器的音量。
- **速度**：0.50× 到 1.25×，每格 0.05。伴奏解码成一条缓冲后用 `playbackRate` 播放，变速时音高会一起变。媒体元素的 `preservesPitch` 在这条路径上没法同时保证进度和跟鼓对齐，所以没有用它。

伴奏和鼓走同一个音频上下文，但伴奏有自己的音量，不经过鼓的软削波，所以放着音乐时敲鼓仍然是立刻出声、可以叠在一起。

快捷键不占用鼓的键：`B` 播放或暂停，`N` 停止，`L` 循环，`[` `]` 后退或前进 5 秒，`-` `=` 调节速度。焦点在滑块或下拉框上时，这些键交给控件自己。

录音开始时，如果伴奏正在播放，会记下它的位置、速度和是否循环。之后按「播放」听这段录音，伴奏会从那个位置一起开始。录音过程中节拍器照常可用，嘀声仍然不会被录进去。

## 鼓谱练习

工具栏上的 **鼓谱** 打开一条练习谱，收起以后鼓面还是满的。十首曲子由易到难，写在 `js/patterns.js` 里，加一首就是再放一个对象。每一小节分成 16 格，对应「1 e & a」。

格子里写着建议按的键。需要两只手的鼓会轮流用它的两个键，比如军鼓是 F、G、F、G。底鼓格子里写「空」，表示空格。

- **练习**：先听一小节预备拍，然后循环这首曲子。游标按音频时钟往前走，下一格会亮。速度默认 60 BPM，可以单独调，不改原来的节拍器。
- **试听**：用鼓的采样把谱子打出来，不记分。
- **判定**：每一击和谱上的音比较。默认窗口大约是 ±100 毫秒，音符排得更密时会自动收窄，避免一击算到相邻的两格。正中是绿色，偏早或偏晚另计，漏掉变红。早和晚按七成算进准确率，漏掉不算。多敲的只显示次数，不扣分。每一圈结束给出百分比。
- **校准**：判定会先减去当前的 `outputLatency`。若你总是被记成晚或早，拖 **校准**。往右是把判定时刻再往后挪。

练习时的嘀声走自己的调度，原来的节拍器会关掉，避免两套拍子叠在一起。伴奏可以同时放。录音仍然只记下你敲的鼓，不记嘀声，也不记试听打出来的音。

快捷键不占用鼓和伴奏的键：`C` 练习或停止，`V` 试听或停止，方向键上、下换一首。焦点在滑块或下拉里时，这些键交给控件自己。

## 手机横屏

整套鼓按横屏来排。竖着拿手机时，会盖住琴面，提示你转成横向。

点 **进入全屏并横屏** 之后，页面会先进入全屏，再尝试 `screen.orientation.lock('landscape')`。支持的浏览器会自己转到横屏。iPhone 自带的 Safari 通常不允许网页锁定方向，这时按提示关掉方向锁，手动把手机横过来即可。工具栏上的 **全屏** 也会做同样的尝试。

横屏以后鼓铺满画面，每面鼓都按手指能按住的大小来排。手指按下的瞬间（`touchstart`）就出声，不是等松手，也不是带延迟的 `click`。同一下触摸不会因为随后的 `pointerdown` 再响一次。一根手指按住再滑到另一面鼓，也会敲响那一面。鼓面区域用 `touch-action: none`，避免浏览器先判断这是不是滚动。页面会阻止滚动、双指缩放、双击放大和选中文字。

## 音色和许可

鼓的声音是真实采样，不是合成器。来源是 **Virtuosity Drums**（Versilian Studios 与 Karoryfer Samples），许可证为 **CC0 1.0**，属于公有领域，可以自由使用、修改和再分发，没有额外的授权问题。

本仓库用的是 mid 麦克风、中等力度的敲击，转成了单声道 44.1 kHz WAV，并切到鼓槌落下的瞬间，文件开头不留空白。18 个采样一共约 1.8 MB，打开页面时解码进内存，敲击时不再下载。电脑上会向浏览器要最小的音频缓冲。安卓（包括三星 Chrome）默认用 `interactive`：`latencyHint: 0` 在部分手机上会退回到很深的输出缓冲，每一击都慢。音频上下文只在第一次触摸时 `resume()`，之后保持运行，并用一段极轻的噪声占住输出，避免系统在两次敲击之间把音轨休眠（休眠后再打开，在三星上可以接近 1 秒）。

「关于」里的 **延迟诊断** 会显示：敲下那一刻的上下文状态、采样是否已全部解码、`baseLatency`、`outputLatency`、采样率、这次是哪种事件触发的、从事件到 `start()` 的时间，以及这次有没有调用 `resume()`。诊断里可以在 `interactive`、`0`、`playback` 之间切换，对比 `outputLatency`。蓝牙耳机或蓝牙音箱还会额外增加大约 100–300 毫秒，网页去不掉，请用手机扬声器或有线耳机对比。

每面鼓有两条采样轮流播放，连击不会那么死板。原库没有单独的中音嗵鼓，这里的中音嗵鼓是高音嗵鼓降低四个半音得来的。

内置伴奏是两段没有鼓的短曲，作者 **Tozan**，发布在 OpenGameArt，许可证同为 **CC0 1.0**。`backing/peaceful3.mp3` 是钢琴加无品贝斯（约 1 分 47 秒），`backing/bgmusic1.mp3` 是钢琴和弦、钟和无品贝斯（约 2 分 16 秒）。上游是 16 kHz 的 Ogg Vorbis。仓库里转成了单声道 44.1 kHz、64 kbps 的 MP3，旋律没有改。播放时整段解码进音频缓冲，进度和变速都走这条缓冲，不再依赖媒体元素的进度条。

## 在自己电脑上打开

采样通过 `fetch` 加载。直接双击 `index.html`（`file://`）时，浏览器会拦住这些请求，鼓就没有声音。请在仓库目录开一个静态服务器：

```bash
python3 -m http.server 8787
```

然后打开 <http://localhost:8787/> 。

## 部署到 GitHub Pages

仓库里的 [`.github/workflows/pages.yml`](.github/workflows/pages.yml) 会在代码推送到 `main` 时，把页面部署到 GitHub Pages。使用前要在仓库设置里把 Pages 的来源选成 GitHub Actions。

1. 打开这个 GitHub 仓库。
2. 进入 **Settings**（设置）→ 左侧 **Pages**。
3. 在 **Build and deployment**（构建和部署）里，把 **Source**（来源）选成 **GitHub Actions**。不要选 “Deploy from a branch”。
4. 把包含这个工作流的提交合并进默认分支 `main`。
5. 打开 **Actions**，确认 “Deploy GitHub Pages” 成功。
6. 回到 **Settings → Pages**，页面顶部会给出网址，一般是 `https://brighthuang84.github.io/drum-kit/`。以设置页上写的为准。

如果 Source 已经是 GitHub Actions，就不用再改别的开关，合并到 `main` 之后会自动部署。

工作流文件必须在默认分支上，GitHub 才会运行它。只存在于尚未合并的分支里时，不会发布页面。

第一次部署时，如果仓库是私有的，Actions 可能停在等待批准（Waiting for review）。打开那次运行，或到 **Settings → Environments → github-pages** 里批准。公开仓库通常不用这一步。

免费的 GitHub Pages 面向公开仓库。私有仓库要看账号是否包含 Pages。

## 重新生成采样

`tools/prepare_samples.py` 会重新下载上游 CC0 采样并写出 `samples/*.wav`。需要本机有 Python 3 和 ffmpeg。下载的原始文件放在 `samples/_src/`，这个目录不会提交。
